# 02 · 弯路与避坑（实测记录）

以下全部是真实踩过的坑，按"现象 → 原因 → 解法"记录。

---

## 1. MySQL 源码编译装了整整半天（最大弯路）

**现象**：宝塔软件商店装 MySQL，源码编译 1–2 小时起，中途还可能因内存不足被 kill。

**原因**：宝塔默认源码编译；容器内存小，编译 mysql 极慢。

**解法**：
- 用官方**预编译二进制**（`mysql-*-linux-glibc2.17-x86_64.tar.xz`），解压即用，3–8 分钟。见 `scripts/mysql-quick.sh`。
- **更快的思路**：预编译二进制本质就是"别人装好的 MySQL 的目录拷贝"。所以把任意一台同架构机器上装好的 `/www/server/mysql` 整个 `cp -a` 过来，`chown mysql:mysql`、初始化数据目录、`/etc/init.d/mysqld start` 就能直接用。
- 下载源顺序：官方 CDN → 清华镜像 → 阿里镜像。

## 2. 宝塔安装脚本在容器里卡死（两处死循环）

**现象**：`install_panel.sh` 装到一半长时间无输出。

**原因**（两处）：
1. `Fix_Apt_Lock()`：函数内部扫描 `/proc/*/cmdline`，容器 /proc 特殊，全量扫描死循环。
2. `Apt_Ready()`：对 apt-get 做探测更新，容器内无意义且可能卡住。

**解法**：装前打补丁（`install-bt.sh` 已内置）：

```bash
sed -i 's#\[ ! -f "/usr/bin/apt-get" \] && return 0#return 0  # container patch#' install_panel.sh
sed -i '/^Apt_Ready(){$/{n;s/.*/    return 0  # container patch/;}' install_panel.sh
```

## 3. sudo 丢环境变量导致强制安装不生效

**现象**：`INSTALL_FORCE=true sudo bash install_panel.sh` 仍然进入交互确认。

**原因**：sudo 默认 `env_reset`，外部 export 的变量进不了 sudo 内部。

**解法**：把 export 写进 sudo 的 bash -c 里：

```bash
sudo bash -c 'export INSTALL_FORCE=true && cd /tmp && bash install_panel.sh -y ed8484bec'
```

## 4. 沙箱重置后一切消失（rootfs 还原）

**现象**：工作区重置，宝塔、站点、数据库全部回到初始。

**原因**：宝塔数据在 rootfs 的 `/www`，重置即清空。

**解法**：
1. 部署**前**就把 `/www` 软链到持久目录（`persist-www.sh`）。
2. 重置后跑 `restore.sh`：重建软链 → 启动面板/nginx/php/mysql → 起隧道 → 恢复站点监控。

## 5. 无公网 IP，网站外面访问不了

**现象**：面板、站点本地都能开，手机打不开。

**原因**：容器是 NAT 出口，没有公网 IP，端口不可达。

**解法**：内网穿透。
- cloudflared quick tunnel（trycloudflare）：免账号，`cloudflared tunnel --url http://127.0.0.1:<端口>`。
- 备用：serveo（`ssh -R 443:127.0.0.1:<端口> serveo.net`）。
- 要固定域名：Cloudflare named tunnel（需有域名，但无需备案）。

## 6. 面板 HTTPS 自签证书打不开/被拦截

**现象**：`https://127.0.0.1:<端口>` 报证书错误。

**原因**：宝塔自签证书。

**解法**：临时隧道给面板套 `https`（cloudflared `--url https://127.0.0.1:<端口> --no-tls-verify`），手机直接访问隧道 https 地址即可。

## 7. 多端口建站的端口选择

**现象**：所有站点挤在一个端口（80/8088），互相冲突。

**解法**：约定端口段 `20001–20050`（50 个），一个站点一个端口：
- 面板添加站点，域名写 `名字.后缀:端口`（如 `test.com:20001`）。
- 端口到公网地址的映射由 `sites-monitor.sh` 自动维护，导航页自动展示。
- 端口段用完后可扩展（改 `ports.txt`）。

## 8. cloudflared 下载慢 / 二进制缺失

**现象**：隧道起不来，日志空。

**解法**：
- 官方地址：`https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64`
- 下载后 `chmod +x`，放工作区复用（沙箱重置后记得重新下载或提前放持久目录）。
- 面板隧道日志 `/tmp/tunnel_panel.log`，网站隧道日志 `/tmp/tunnel_web.log`。

## 9. PHP 编译也慢（可选优化）

**现象**：面板装 PHP 8.1 也走编译，几十分钟。

**解法**：
- 不着急的话等它编译完（面板全自动）。
- 着急：面板 → 软件商店 → PHP → 已有二进制安装源（若有），或先跳过 PHP 只跑静态站 + MySQL。
- 容器内 PHP-FPM 启动：`/etc/init.d/php-fpm-81 start`（没有 systemd）。

## 10. 常驻进程被沙箱回收

**现象**：过一段时间监控/隧道进程没了。

**原因**：沙箱可能回收长驻进程。

**解法**：
- 监控脚本用 `nohup ... &` 且日志重定向（已在脚本内）。
- 重置/重启后统一跑 `restore.sh` 一次，全部进程会拉起。

## 11. 测试反馈修复合集（2026-11 实测）

以下 5 个坑是真实用户部署时踩到并修复的，脚本已全部内置修复：

**11.1 sed 分隔符与替换文本撞车（install-bt.sh）**
- 坑：给官方安装脚本打容器补丁时，sed 用 `#` 作分隔符，但替换文本里也含 `#`（`# container patch`），直接报 `sed: unknown option to s'`，`set -e` 下整个安装中断。
- 修：分隔符改用 `|`，且打补丁前先 `grep -q` 确认目标行存在（官方脚本更新了也不会死）。

**11.2 缺 libaio.so.1，MySQL 初始化失败且错误被吞（mysql-quick.sh）**
- 坑：依赖安装用 `2>/dev/null || true` 把失败吞了，`mysqld --initialize` 报错也被吞，只在日志里留一句"初始化失败"。
- 修：依赖安装后显式 `ldconfig -p | grep libaio.so.1` 检查，缺了就 `apt-get update` 重装，仍缺则直接报错退出并告诉你怎么修；初始化错误不再吞，详细原因进 `/tmp/mysql_quick.log`。

**11.3 PHP 预编译包解压报 EXDEV（php-offline.sh）**
- 坑：`/www` 是软链到持久目录的（跨文件系统），直接在 `/` 下 `tar -xf` 解压含硬链接的包会报 `Cannot hardlink ... cross-device link`。
- 修：先解压到 `/tmp`（同一文件系统内），再 `cp -a` 到目标——`cp -a` 跨设备会自动把硬链接降级为普通文件复制，不报错、内容完整。

**11.4 离线包下载了却没用上（one-click.sh 环境变量）**
- 坑：one-click.sh 把 MySQL/PHP 预编译包下载到 `bt_res/`，但子脚本读不到 `$WORK`（变量没 export），结果 MySQL 又走慢速官方 CDN、PHP 又走 20-40 分钟源码编译。
- 修：`export WORK DOUBAO_WORKSPACE`，子脚本也各自兜底取 `pwd`。

**11.5 空目录建软链报 File exists（persist-www.sh）**
- 坑：沙箱里 `/www` 是空目录时，`ln -s` 直接报 `File exists`。
- 修：先 `rmdir` 空目录再建软链；有数据的目录才走迁移。

## 12. 下载速度：GitHub Release > 清华镜像 > 官方 CDN（实测）

- MySQL 预编译包默认从本项目 GitHub Release 下载，走 `fetch.sh` 多通道（GitHub 加速镜像 → 代理 → 直连），实测比 MySQL 官方 CDN（国外源）快很多。
- 失败自动降级：清华镜像 → 官方 CDN（最慢，仅兜底）。
- 一次下载成功后会留在 `bt_res/`，下次部署秒装。

## 13. 沙箱/容器重置全踩坑实录（2026-11 实测）

豆包工作区（沙箱）可能随时被重置：**数据目录里的东西都在，但系统层的东西会被清空**。
数据放哪、什么会丢、怎么一键恢复，实测结论如下：

### 13.1 重置后什么会丢、什么还在

| 类别 | 例子 | 重置后 |
| --- | --- | --- |
| 你的网站数据 | 数据库、网站文件、面板配置（在 `/www` → 持久目录） | ✅ 完好 |
| 系统用户 | `mysql`、`www`（跑数据库/网站的账号） | ❌ 被清 |
| 服务脚本 | `/etc/init.d/mysqld`、`/etc/init.d/php-fpm-81`、`/etc/init.d/bt` | ❌ 被清 |
| 运行时库 | `libaio.so.1`、`libssl.so.1.1`、`libncurses.so.5`、`libzip.so.4`、`libluajit-5.1.so.2` | ❌ 被清 |
| `/www` 软链接 | 指向持久目录的软链 | ❌ 丢失（需重建） |

> 一句话：**持久目录 = 你的数据；系统层 = 每次重置要重新搭的脚手架**。
> 所以项目把 `/www` 整个软链到持久目录（数据永不丢），系统层交给 `restore.sh` 自动重建。

### 13.2 这次实测踩到的坑（逐项修复）

**① /www 软链丢失 → 网站文件"不见了"**
```bash
sudo ln -s <工作区>/bt_data/www /www
```
（如果是空目录残留，先 `rmdir /www` 再建软链——见 11.5）

**② mysql/www 系统用户被清 → mysqld 起不来（unknown user mysql）**
先看持久数据属主 uid，再按同 uid 重建，属主才对得上：
```bash
sudo useradd -r -s /sbin/nologin -u <数据属主uid> mysql
sudo useradd -r -s /sbin/nologin -u <数据属主uid> www
```

**③ 缺 libaio.so.1 → MySQL 起不来（error while loading shared libraries）**
```bash
sudo apt-get install -y libaio1
# apt 不可用时手动装：从 cn.archive.ubuntu.com 下载 libaio1_0.3.112-13build1_amd64.deb 再 dpkg -i
```
（注意：镜像返回 193 字节的 HTML 说明版本号/路径不对，是 404 错误页，不是包！）

**④ 缺 libssl.so.1.1 → php-fpm 起不来**
Ubuntu 22.04 默认只有 OpenSSL 3，宝塔 PHP 8.1 预编译版链的是 1.1：
```bash
# 从 focal 仓库下载（cn.archive 实测可用）：
# libssl1.1_1.1.1f-1ubuntu2.24_amd64.deb  →  sudo dpkg -i
```

**⑤ 缺 libncurses.so.5 → mysql 命令行客户端起不来**
22.04 只有 6 版，软链兼容即可：
```bash
sudo ln -sf /usr/lib/x86_64-linux-gnu/libncurses.so.6 /usr/lib/x86_64-linux-gnu/libncurses.so.5
sudo ln -sf /usr/lib/x86_64-linux-gnu/libtinfo.so.6     /usr/lib/x86_64-linux-gnu/libtinfo.so.5
```

**⑥ 缺 libzip4 → php zip 扩展加载失败**
```bash
sudo apt-get install -y libzip4   # jammy 版本 1.0.1-0ubuntu1
```

**⑦ 系统 libluajit 缺 lua_getexdata 符号 → 宝塔 nginx 起不来**
Ubuntu 的 libluajit-5.1-2 是 Debian 裁剪版，宝塔 nginx 需要 OpenResty 补丁版：
```bash
# 用项目 fetch.sh 拉源码编译（约 1 分钟，实测通过）：
bash scripts/fetch.sh "https://github.com/openresty/luajit2/archive/refs/tags/v2.1-20240815.tar.gz" /tmp/luajit2.tar.gz
cd /tmp && tar -xf luajit2.tar.gz && cd luajit2-2.1-20240815
sudo make -j4 PREFIX=/usr/local && sudo make install PREFIX=/usr/local
sudo cp /usr/local/lib/libluajit-5.1.so.2 /lib/x86_64-linux-gnu/libluajit-5.1.so.2 && sudo ldconfig
# 验证符号： nm -D /lib/x86_64-linux-gnu/libluajit-5.1.so.2 | grep lua_getexdata  → 有输出即成功
```

**⑧ /etc/init.d 脚本被清 → 服务没法 start**
```bash
# mysqld：从宝塔自带模板重建
sudo cp /www/server/mysql/support-files/mysql.server /etc/init.d/mysqld && sudo chmod +x /etc/init.d/mysqld
# php-fpm-81：模板见 restore.sh（含 start/stop/restart 三命令）
```

**⑨ php zip 扩展与系统 libzip 版本符号不匹配 → php-fpm 整体起不来**
zip.so 报 `undefined symbol: zip_libzip_version` 时，直接禁用该扩展（不影响网站）：
```bash
sudo sed -i 's|^extension = zip.so|;extension = zip.so|' /www/server/php/81/etc/php.ini
```

**⑩ 面板/网站都起来了，但手机访问不了 → 网址是临时的**
`*.trycloudflare.com` 是临时随机地址，重置即失效、且不会回到同一个。
重置后跑一次 `bash scripts/tunnel.sh` 重新开隧道，会得到**新的**临时网址（地址会变是正常现象）。

### 13.3 终极解法：跑 restore.sh

以上 ①–⑨ 已全部内置进 `scripts/restore.sh`（自动检测缺失并修复，先 apt 后手动兜底），
重置后只需一句：
```bash
bash scripts/restore.sh
```
它会自动：重建 `/www` 软链 → 重建 mysql/www 用户 → 修依赖库（含 luajit 编译）→
重建 init 脚本 → 禁用不兼容 zip 扩展 → 拉起面板/nginx/php/mysql → 再跑 `bash scripts/tunnel.sh` 开公网隧道。
